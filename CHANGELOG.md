# Changelog

## 0.6.0 (2026-11-08)

- Relevant Solutions gate (`hubofhubs.the_intelligence.subconscious.relevant_solutions.gate`): a model pass only for solutions at or above a records-index score (73 by default, fixed from the hub's 62 relevance cases by the precision-at-least-half rule; `threshold_from_cases` re-derives it for a consumer's own records).
- Solution Passes (Critical Thinking): the work-outcome metric (score = B - 0.5 N - 0.1 L - 0.1 K; weights and gate fixed before any run), its six work-request and four no-solution cases, and the runner that scores them. Built on esoi 0.6.0's `solution_consideration` and `solution_relevance`.
- Quick acknowledgement in two stages: the code-written placeholder (stage `placeholder`) then a fast-model acknowledgement (`model_ack_event`, `ack_stage`, `Emitter.model_ack`, stage `model`).
- Requires esoi 0.6.0.
- Decision Check: `CallPool` runs a check's calls with a ceiling on calls in flight; `CheckBinding.hedge_after_seconds` sends a call still unanswered after that long once more and takes the first answer that is not a failed call (the copy left running is never read). The reply result reports `hedged`.
- Decision Check (reply): stages overlap on one pool of at most `parallel` calls in flight: a view's flagged spans go to confirmation as soon as that view answers, a confirmed span goes to repair as soon as it is confirmed. A view's spans are confirmed together (each judged on its own in a numbered list); two confirmations come first and the third is asked only on a split, which cannot change a two-to-nothing majority. Every flagged span is still confirmed and no confirmed failure ships unchanged. `UNCONFIRMED_REPLY` is exported.
- Communication policy: an interim the Mind marks `data["announce"] = True` (`ANNOUNCE_KEY`: where things stand and what happens next, sent before the work) is a status, never kept, however long the turn has run.
- Communication policy (`hubofhubs.the_consciousness.communication`): one decision per Mind event, `communicate(event, turn)`, says whether the person gets nothing (the transparency stream stays inspectable), a status (shown now, replaced, never kept), a durable message (the final answer; a usable partial result after a long stretch with another long stretch to come) or an ask (durable plus a notification: blocked on the person, or a finding marked `notify`). Structure only, never the words; `LONG_STRETCH_SECONDS` is a parameter of `CommunicationPolicy`. `TurnCommunicator` keeps the turn's clock. How-to: `docs/how-to/decide-what-a-person-is-told.md`.
- Quick acknowledgement (`hubofhubs.the_world.tools.acknowledge`): a turn opens with a status event marked `kind: "ack"`, written by code and sent before any slow work, within `ACK_WITHIN_SECONDS` (one second) of the turn's start. A status is replaced by later events and never stored, unlike `EVENT_INTERIM`. `ack_event`, `is_ack`, `Acknowledger` (sends once, records `acked_after`) and `Emitter.ack()`, all in `hubofhubs.api`. The acknowledgement has a second stage: after the code-written placeholder, one fast-tier model call started at the turn's start writes a one-sentence ack about the actual request, sent as an ack status marked `stage: "model"` (`model_ack_event`, `ack_stage`, `Emitter.model_ack`, `STAGE_MODEL`, `MODEL_ACK_TARGET_SECONDS` of 3 seconds); the reply path never waits for it, and a late or failed one is dropped, logged and counted. How-to: `docs/how-to/acknowledge-a-turn.md`.
- Decision Check (reply): detection and confirmation run on every flagged span (three independent confirmations each, on top of the cap; most must say it fails). A confirmed failure never ships unchanged: a model rewrite when a call is left (rewording only, no new figure), else code removes its whole sentence; a reply left empty says plainly what could not be confirmed. Each span removed instead of rewritten is returned as a `confirmed_failure` mistake record (`CONFIRMED_FAILURE`). Replaces the rule that confirmed a span only when the budget could also repair it.
- Decision Check (reply): a repair only removes or rewords what the reply already says; a rewrite holding a figure the span did not hold becomes a removal.
- Decision Check (reply): a span the repair would remove goes only when most of three independent confirmations say it fails (two more calls, only for a removal); spans are budgeted at four calls each, and a reply left unchanged is `held`.
- Decision Check: `majority_vote` arm (`MajorityVote`), the agreement check with a disagreement settled by the views' majority; only a tie goes to the adjudication call. Outcome `majority` added.
- Decision Check: a span a reply check removes takes its whole sentence with it, so a removed clause never leaves a fragment ("..., and").

## 0.5.1 (2026-11-08)

- Decision Check (`decision-check`, `DecisionChecking`, in Critical Thinking): a cheap model gives a reliable decision through structure. A consumer hands a `CheckBinding` (the options and, per view, an instruction and the one slice of evidence it sees, plus any vote it already holds and a call cap); the views run in parallel, agreement is accepted at no further cost, a disagreement goes to one call that sees only the disagreeing views and must quote evidence the code finds in them or the check abstains, and a reply is repaired only at the spans an independent call confirms. Arms: `agreement_check`, `agreement_with_known_mistakes`, `single_verify` (the bound) and `draft_as_given` (the floor). The learning loop (`Mistake`, `MistakeLog`, `overruled_mistakes`, `distill`, `LineBook`, `adopt`, `retire`, all in `hubofhubs.api`) turns found mistakes into known-mistake lines offline and adopts a line only when the check's score rises on held-out cases. `CriticalThinking.check_decision` is the composition step. Offline metric `evaluation/decision_check`.

## 0.5.0 (2026-11-07)

- Two Mind solutions, each with competing arms and an offline metric. `route-a-request` (`RequestRouting`) decides once whether a request asks to be told something, to have something done, to have text written in the reply, or is not yet understood: the arms are `single_classifier` (one cheap model call), `plan_derived` (the route read off the Planner's plan; a consumer subclass supplies the draft and clarify signals of its own planner) and `majority_floor`. `resolve-a-reference` (`ReferenceResolving`) ties a phrase to one of a list of candidates or abstains: the arms are `exact_match` (id, whole name or alias, whole words of one name), `model_judged` and `shared_words` (the bound that matches look-alikes). Both are in `hubofhubs.api`; the paid arms are not yet measured live.
- Response Quality gains the generic reply guards as arms, each judging one criterion and able to repair: `grounded_figures` (a sentence stating a figure the evidence lacks is a finding and `repair` takes it out), `em_dash_free` (`repair` rewrites each em dash by punctuation rules) and `date_arithmetic` (a wrong "N days from today" or "N days before/after an event (date)" count). The interface gains `repair(response, evidence)`. Names exported in `hubofhubs.api`: `evidence_of`, `strip_unsupported`, `remove_em_dashes`, `clean_value`, `relativize`, `clean_roots`, `dates_in`, `month_of`, `today_of`, `day_count_errors`, `event_offset_errors` and the month and date patterns. Offline metric cases: `evaluation/response_quality`.

## 0.4.0 (2026-11-07)

- References resolved for a card's content are remembered for a minute (`resolve_remembered`, cleared by `clear_resolution_memo`, exported in `hubofhubs.api`; the consumer clears it after any write), so the turn-start assembly and the reads after it do not fetch the same live data again one after the other. A turn-start assembly that hit its deadline but holds context counts as context in hand for `TurnCardCache`'s cheap follow-up reads.

- Cheap-first context. `meta["context_depth"] == "retrieve"` (`retrieve_only`, `with_retrieve_depth`, `cheap_result_is_decisive`, all in `hubofhubs.api`) asks an assembly for search and score only: the vector arm skips query generation and hit review, the hybrid skips consolidation. `TurnCardCache` serves a read after the turn-start assembly on that path (`cheap_followups`, default on) and escalates to the full assembly when the cheap result is empty or has no card at `DECISIVE_CARD_SCORE`. Two arms asking the same selection question at once share one model call (`single_flight`). The within-card file ranking is skipped for a card of `RANK_ONLY_ABOVE` (5) or fewer files.

- Critical Thinking's pursue step sends fixed text (`still_working_line()`, `unmet_message(tried)`), never the checker's reason or next action, which stay in the result's `missing` for logs.

## 0.2.0

- **One function, `hubofhubs.run(id, input)`, replaces `ask` (2026-11-02).** The id is a solution id (`card-store`, `web-search`, `the-science`, `the-subconscious`, `critical-thinking`) or `hub-of-hubs` for the whole hub, which returns a `Result` (answer, items with sources, trace, arms, note, events). `ask` and `stream` no longer exist, and the CLI is `ahohs run "<input>" [--id ID] [--arm ID=ARM] [--lock FILE] [--json]` (no `--seat`). `hubofhubs.run(CardStore)` returns the typed ready handle. `hubofhubs.needs(id)` lists what a setup lacks; a call that cannot run raises `esoi.entry.Pending` naming the key or install. Keywords override only what differs: `arms=`, `options=`, `provided=`, `lock=`, `environ=`.
- **Composition arms in code** for the-world, the-subconscious, the-mind, system-integrity and the-assembler, plus implementations for the-learning, the-hands and critical-thinking (links held to their evidence).
- **hold-the-intents is dissolved**: its research area now sits under the-mind.
- **Composites build a member on first use**: the whole-hub question needs only the search key, and `the-subconscious` runs offline; the model, the risk watch, the acting seat and the audit are built when first used.
- **Install pins the extras; esoi is installed from the `@v0.4.0` tag with the same direct-URL string every consumer uses** (two different direct URLs for one package make pip fail, as on 2026-10-19). Every library moves to its next tag in every consumer at once, at each release.
- New pages: glossary, the mind map, compared, and `CONTRIBUTING.md`.
