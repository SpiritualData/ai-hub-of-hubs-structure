# Changelog

## Unreleased

- **`hubofhubs.terminal`: pure renderers from run events to blocks, with no UI library (2026-11-01; offline).** `Block` (kind, text, rows, state, fold key, style, actions), `render(event, state)` and `settle(state)` for the `work_trace` (a live line of the newest page opened, a settled one-line summary that names records, pages and papers, groups behind it), `interim` (kept messages, earlier ones folded into "Earlier updates (n)" with a preview), `decision` (an ask with options, free text and "Not now" that keeps it open, or "Waiting on <name>") and `result` (a stopped reason with Continue) events, plus `to_text`. The words are the Quest app's English; `tests/test_terminal_drift.py` fails when they or the app's `workTrace.ts` rules stop matching. First slice of phase 0 of `docs/explanation/terminal-harness.md`: no widgets, no CLI, no recorded logs yet. Tests: `tests/test_terminal_render.py`. No model call was made.

- **`hubofhubs.ports.trace` and `EVENT_WORK_TRACE`: a typed, reader-safe work trace (2026-11-01).** `WorkTraceEvent` (one unit of work, latest event per `step_id` replaces earlier ones), the allowlist projector `project` (named fields only; domains instead of URLs; no queries, content, reasoning, paths or tool arguments; labels trimmed to 80 characters and free of newlines and em dashes; at most 20 items; `records` become counts only when `viewer_may_see_titles=False`), `validate`, and `WorkTrace`, a helper any solution uses to emit (coalesces running updates to about four a second, always sends the final state, keeps a compact `summary()`). `EVENT_WORK_TRACE = "work_trace"` is LIVE only. Schema: `docs/reference/work-trace-event.schema.json`. Tests: `tests/test_ports_trace.py`. No model call was made.

- **The overseer digest can carry a situation standard and the draft's measurements (2026-11-01).** `build_digest` takes `situation_standard`, `draft_measurements` and `draft_chars` (how much of the draft is shown); they sit in the protected tail beside the draft and the mixin widens the digest budget by their room. `PlanDecision.reply_shape` is the planner's self-reported shape of the reply (a small enum the consumer defines). Tests: `tests/test_risk.py`. No model call was made.

- **`claude_cli`, the keyless Claude Code arm, is the default of `call-a-model` (2026-10-31).** `hubofhubs.models.claude_cli.ClaudeCliProvider` (moved in from a consumer) drives `claude -p` on the operator's subscription login: no key, no per-token billing; it needs only the `claude` executable. Settings are constructor arguments (`claude_path`, `timeout_seconds`, `effort`, `haiku_thinking_tokens`, `plan_thinking_tokens`, `environment`) and its collaborators are passed in (`usage_limits`, `newest_family_id`); it reads no environment, and without an `environment` the child inherits the process's with the subscription-forcing removals applied through `env -u`. `hubofhubs.assemble()` now builds `call-a-model` and `model-call` with no argument; every other vendor stays one argument away (`arms={"call-a-model": "gemini"}`, or `multi_provider` with `options={"call-a-model": {"primary": ...}}`). The organization decided that its own configuration runs on the Claude Code subscription; the seat's metric does not rank vendors, so the choice is not a measured win (the arm's first recorded run is a three-case sample of `call_a_model`). Tests: `tests/test_models_claude_cli.py`.

- **Requirements declared on every arm; docs in the four Diataxis folders; offline coherence check (2026-10-31).** Every arm sets `REQUIRES` (`api` with a secret key variable, official links and dated free-tier and rate-limit statements copied from each vendor's page; `python` naming the `pyproject.toml` extra; `binary` for the Claude Code runners and the ACP agent; `service` for SearXNG and Qdrant; `download` for the fastembed model with its size; `isolatable` for the arms behind a process boundary), shared pieces in `hubofhubs/arm_needs.py`; `ENVIRON` is no longer needed on the arms that use it. Generated: `docs/reference/requirements-by-arm.md` (`scripts/status.py`) and `.env.example` (`esoi requirements --package hubofhubs --env-template .env.example`). `tests/test_requirements.py` checks that every arm declares, every python requirement is provided by the extra it names, and the selected arms resolve together offline; `--online` was run once in a throwaway virtualenv. Docs moved: tutorials, how-to, explanation and reference folders with `docs/README.md` as the index, one new tutorial (`tests/test_tutorial.py` runs it) and one new how-to; the announcement and article drafts moved to `drafts/`. The README lead column and `docs/explanation/how-we-measure.md` use the owner's selection rule: the highest result at the latest comparable stage is used, labelled significant or a best guess, not yet significant. No model call was made.

- **`SearchHit` carries passages, their kind and the caller's instruction (2026-10-31; backward compatible).** A hit gains `passages` (the separate passages for the page, uncapped) and `passage_kind` (`verbatim` when the backend quotes the page, as Anthropic native search does with `cited_text`; `attributed` when a model wrote a sentence and tied it to the page, as Gemini grounding supports do; `snippet` for the excerpt a search API returns). `snippet` is unchanged (the first passage, or Gemini's joined text capped at 300 characters) and `date` is filled where the backend has one (Serper, Brave, Tavily, SearXNG, Anthropic `page_age`; Gemini grounding exposes none). `SearchBackend.search` gains an optional `instruction` keyword: model-backed arms (gemini, provider) pass it to the model, the others accept and ignore it, and the provider arm hands it to a provider only when given. Model providers' `web_search` rows may carry `passages`, `passage_kind` and `date`. The `search_backend` rows for gemini and provider were re-recorded against the changed code. Tests: `tests/test_ws_search_passages.py`.

- **README rebuilt around the evidence; narrow solutions get their own ids (2026-10-31).** The README is now a one-line promise, the one-line use, a generated evidence table (one row per recorded check: what it does, the common-sense check, cases and source, the selected arm with pass rate and 95% interval, cost per passing case, whether the lead is significant with test and p, and what public research says), how we measure, and an honest list of what is not measured yet. `hubofhubs.evidence_summary` builds the table and the list from `esoi/results.csv`, `esoi/per_case.csv` and `esoi/evidence.csv` with the esoi library's statistics, `docs/reference/evidence-labels.csv` holds the plain words, and `scripts/status.py` writes them into the README and `docs/reference/evidence-by-arm.md`. Three seats that were really narrow solutions are declared under their own ids: `choose-a-model-tier` (was `reason-and-answer`), `read-registry-freshness` (was `stay-current`) and `score-hub-connections` (was `connect-any-integration`), with their arms, metrics and results; the Mind, Learning and Hands seats stay as specified seats with no arm. Descriptive wording for the seats, arms and metrics the README shows is rewritten and no longer marked unconfirmed. The evaluation component folders keep their names so the recorded rows still match. No model call was made.

- **`hubofhubs.orchestrate.phases.run_phases` (2026-10-30; built and tested offline).** The turn as a chain of phases sharing one run-local namespace: each phase returns a terminal result to end the turn or `None` to go on. No model call was made.
- **`hubofhubs.orchestrate.answer`: the answering mixin (2026-10-30; built and tested offline).** `AnsweringMixin` (model choice by hint, plan tier and default; the grounded answer with the system-prompt voice and the layered form; the sub-question fan-out and merge; the after-deep, after-queued and task-report syntheses with their safe fallbacks; the claim check) holds the flow only. Every sentence the model is told or a person may read as a fallback, the grounding renderers and the logger are the `AnswerKit` the host supplies. No model call was made.
- **`hubofhubs.orchestrate.oversee`: the loop's overseer mixin (2026-10-30; built and tested offline).** `OverseeMixin` (spend metrics, operation lines, the capped digest call, the fire-and-forget consult with the planner-tier retry of a degraded verdict, collect, and the late background follow-up) reads only what `OverseeHost` names: a config view, a provider, a tier registry, an optional escalation sink and four hooks the host supplies (summarize an observation, build the digest, consult the overseer, raise a late human escalation). The overseer prompt, digest wording and the escalation's shape stay the consumer's. No model call was made.
- **`hubofhubs.orchestrate` gains the per-turn machinery (2026-10-30; built and tested offline).** `turn.TurnCardCache` (one in-run, query-keyed cache of context assembly shared by the turn start and the mid-loop reads: eager pre-fetch, join or reuse, partial results never cached) and `turn.Emitter` (forwards progress events to the sink the run's mode chose and lets a live run drop to the background sink), and `watch.worth_a_look` (the free gate that decides whether a step is worth waking the overseer). Depend only on the hub's ports. No model call was made.
- **`hubofhubs.orchestrate` gains the decision value and the cascade's structural half (2026-10-30; built and tested offline).** `plan.PlanDecision` (the planner's next-step decision as a plain value), `cascade` (`escalation_spec`, `should_escalate`, `truncate_keep_both_ends`, `apply_review` and `user_goal_fallback`, which take the consumer's default goal and question as arguments; the review prompt and the description of a decision for the reviewer stay the consumer's) and `schema` (`strip_schema_descriptions`, `compact_schema` with the consumer's list of descriptions to keep, and `normalize_choice` for a closed vocabulary). No model call was made.
- **Scoring is per seat, not per area (2026-10-30).** The 72 research areas are categories inside the 12 top-level seats (`hubs.csv` `seat`, already complete: 11 seats own areas). The scorer now checks seam, selectable, by configuration, vendor branches and fake hub once per seat (`evaluate_seats`, `registry.AREA_KINDS` and `SEAT_KINDS`), and a consumer binds one row per seat it uses (`seat`, `areas`, `seam_solution_id`, `vendor_terms`, `code_paths`). An adopt or coexist area no arm covers is an arm gap (`arm_gaps`), not a missing binding. Registered, fresh and no-reinvented stay per area. A row naming only an `area` still binds that area's seat, an area under the wrong seat is refused, and the per-area facts stay in the result. Weights and thresholds are unchanged; the case set shrinks from 456 to 271 because the connection checks are no longer repeated per area.

- **The reasoning loop's generic leaves move in from the consumer: `hubofhubs.orchestrate` (2026-10-30; built and tested offline).** `staged_plan` (the planner's `deep_subtasks` as ordered stages: normalize, cap, split into sequences, `run_when`), `limits` (the loop's default bounds and the two structural checks on a deep result, `result_reports_something` and `result_landed_work`) and `text` (`ellipsize`, `sentence`, `clip_head_and_tail`). Prompt text, tool vocabularies and settings stay the consumer's. Standard library only; nothing reads the environment. Tests moved with the code. No model call was made.
- **Prompt specs move in from the consumer (2026-10-30; built and tested offline).** `hubofhubs.models.prompt_spec`: `PromptSpec`, `PromptRegistry` and the always-appended no-em-dash rule. The consumer's collaborators are injected with `bind_spec_class(tiers, on_render)` (its tier names and the usage-log hook called on every render); solution and metric ids stay plain strings that the consumer checks against its own records.
- **Three generic helpers move in from the consumer (2026-10-30; built and tested offline).** `hubofhubs.act.secret_redaction` (secret-value redaction for text a service hands out; a consumer adds key shapes of its own as `extra_patterns`, so no vendor-of-the-consumer prefix is in the hub), `hubofhubs.act.signature_probe` (which keywords an installed callable accepts, and the filter that drops the rest, for version skew between separate deploys) and `hubofhubs.recall.conversation_card_builder` (a conversation as a source in a context card, with an optional origin stamp). Standard library only; nothing reads the environment. Tests moved with the code. No model call was made.
- **act-in-the-world: the deep-work runners move in from the consumer (2026-10-30; built and tested offline, none selected, none measured).** `hubofhubs.deep` holds `launch` (the pure `claude -p` argv builder and the frozen `DeepLaunchSettings`), `settings` (`GoalSettings`: the wall-clock cap, the review interval, the launch flags, the sessions directory, the escalation marker, the run-id variable name, a standing-instructions callable, a requester hook, the child environment, and the `UsageLimits` and `PromptBudget` collaborators; a value or a callable read on every use), `contract` (timeouts and model gating, the process-group stop, review parsing, the worker envelope, prompt composition, `GoalRunner`, `SubprocessConfig`), `session` (reading the worker's own session record: the live monitor, resume lookups, end-of-run diagnostics, landed file changes), `subprocess_runner` and `stream_runner` (the one-shot and the steerable stream-json Claude Code runners) and the `acp_*` modules (the Agent Client Protocol runner; the `acp` package is the new `acp` extra, imported inside one function). Registered as the arms `subprocess_goal_runner`, `stream_json_goal_runner` and `acp_deep_runner` of the `act-in-the-world` seat. Nothing reads the environment or a process-wide state, and the hub names no consumer: the escalation marker, the `QAR_*`-style names and the escalation value type are the consumer's to pass. The standard prompt texts (liveness review, headless run contract) are the hub's. No model call was made.
- **remember-and-recall: the vector and BM25 retrieval arms move in from the consumer (2026-10-30; built and tested offline, none selected, none measured).** `hubofhubs.recall.qdrant_store.QdrantVectorStore` (embedded or server Qdrant, one collection per vector size with the scope as a payload filter, fingerprint `sync`, the store fence, relabel and read-vectors maintenance; extra `qdrant`), `embedders` (Voyage AI and OpenAI factories, embedder ids, the measured memory bound of 16 texts per batch; extras `voyage`, `openai`), `card_vectors` (a read-only reader over a mounted store's points on another backend, structurally unable to write), `vector_scopes` (`SeedItems`, the seeded-card partition scope), `vector_assembler.VectorContextAssembler` (parallel multi-query search, optional model query generation and hit review, the raw-similarity confidence gate, specificity-then-recency ranking, id-ordered render, the scope-tag fence, the cold-start seed with a ceiling, association record with a capacity bound), `bm25_store.BM25ContentStore` (BM25 over file content, refreshed by hash; extra `bm25`), `hybrid_assembler.HybridContextAssembler` (keyword and vector arms fused by weighted reciprocal rank, deadline-aware partial results, one consolidating pass) and `card_selection` (the card relevance pass, batched file ranking, the consolidating pass and the selection memo). `ContextAssemblerBase` and `VectorStoreBase` are ports (`hubofhubs.ports.context`). Settings are arguments and nothing reads the environment: the collection prefix, the embedded store's default folder, the seeded-card scope (its digest is part of every stored point and point id, so a consumer with earlier data passes the scope it wrote under; `scope_hash` and `point_id` are pinned by a test), the batch size and length cap, the skip set, the seed ceiling and thread name. Every prompt is data the consumer can replace (`SelectionPrompts`, `VectorPrompts`, `query_prompt`); the defaults are the standard texts. The hybrid takes the consolidating pass as `consolidate_fn`. Tests moved with the code; the BM25 tests run against a stand-in for `bm25s`. No model call was made.
- **Registry: a machine-readable `call` per area, and the connection checks read only the areas that should be connected (2026-10-30).** `hubs.csv` gains `call` (adopt, coexist, keep, watch or avoid; blank counts as coexist), filled from each recommendation. The checks that need a consumer to have connected an area (by configuration, one seam, selectable, a fake hub) are cases only for areas whose call is adopt or coexist, and the scorer's `seam_share` and `selectable_share` are over those areas (`to_connect`, with the unbound ones listed as `unconnected`). Weights and thresholds are unchanged. A consumer is no longer behind on an area the research says to keep, watch or avoid.
- **Scholarly search: an OpenAlex arm of the `know-the-world` seat (2026-10-30; built offline, not selected, not measured).** `hubofhubs.science.openalex.OpenAlexWorks` (`@implementation("know-the-world", "openalex")`, extra `science`) searches works with year and open-access filters and returns title, authors, year, venue, DOI, citations, an abstract rebuilt from the inverted index and a landing link, with a typed error per failure, a cache, spacing and a daily cap. `hubofhubs.science.crossref.lookup_doi` checks a DOI. Port values in `hubofhubs.ports.scholarly`. Key and contact address are arguments. See `docs/explanation/science-search.md`.
- **Scholarly search review fixes (2026-10-30).** The result states that titles and abstracts are untrusted third-party text and that only abstracts were read; titles, authors and abstracts are one line each; a landing page must be http or https; searches leave retracted works out (`is_retracted:false`, `include_retracted` to keep them) and a DOI lookup marks one RETRACTED; the cache holds at most `cache_size` (256) entries, least recently used out; `limiter=` lets a consumer keep one daily count across rebuilt arms; new `hubofhubs.science.citations` compares DOIs in a reply with the DOIs a turn held.
